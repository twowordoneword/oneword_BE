# 뮤징(musing) — 추천 알고리즘 설계

> 앱의 핵심 기능. "그날의 기분·날씨·계절·취향"에 **감정적으로 어울리는 곡 한 곡**을 고른다.
> 기존 프론트 로직(핸드오프 §5, Last.fm 기반)을 **상업 이용 가능 + 프라이버시 세이프**하게 재설계한 문서.

---

## 1. 설계 원칙 / 제약

- **품질 우선**: 장르 인기차트에서 무작위 추출이 아니라, 감정을 좌표로 매칭한다.
- **상업 이용 가능한 소스만**: Last.fm(상업 별도계약 필요)·Spotify(2024-11 신규앱 차단) 배제.
- **프라이버시 세이프**: 추천 입력은 `mood·weather·date·seedTrack`뿐. **일기 제목·본문은 외부로 전송하지 않는다.**
- **LLM 미채택**(근거 ADR-011): 할루시네이션·비용·사생활 문제. 텍스트 이해는 향후 **온디바이스**로만 확장.

## 2. 데이터 소스

| 용도 | 소스 | 비고 |
|---|---|---|
| 후보곡 풀 | **Apple Music RSS 차트**(storefront kr/us, 장르별, 최대 300, 무인증 JSON) | 무료·상업 가능 |
| 취향(seed) 확장 | **iTunes Search/Lookup**(seed 아티스트의 곡 + 동일 장르) | Last.fm '유사 아티스트' 근사 |
| 감정 특성값 | **ReccoBeats**(무료·**상업 이용 허용**) 또는 **Essentia 자체분석**(iTunes 미리듣기 분석) | ReccoBeats=빠름·곡 매칭 필요 / Essentia=느림·매칭 불필요. 값은 모두 `tracks`에 캐싱 |
| 커버·미리듣기 | **iTunes Search** | 스토어 배지 근접 표기 조건 준수 |

> ⚠️ 구현 시 확인: ReccoBeats가 **곡 ID로 특성 조회**를 지원하는지(쉬움) vs **오디오 파일 업로드** 필요(무거움). 후자면 Essentia 자체분석 비중을 높인다.
> ⚠️ ReccoBeats 곡 메타는 Spotify 유래이므로 **감정 특성값만** 쓰고, 표시용 메타·커버는 iTunes에서 받는다(약관 준수). 특성값은 `tracks`에 반드시 캐싱.
> 📌 **AcousticBrainz 덤프는 채택하지 않음**(수십 GB 저장·운영 부담, 2022년 컷오프). 옛날 곡을 포함한 커버리지는 **온디맨드 Essentia 분석**으로 대체.

### 2.1 특성 소스 추상화 (FeatureProvider)

곡 특성을 가져오는 부분을 인터페이스로 추상화한다. 추천 본체는 그대로 두고 **구현체만 교체**:
- **MVP**: `ReccoBeatsProvider` — 붙이기 쉬움(1~2일), 빠른 시작
- **강화/폴백**: `EssentiaProvider` — 미리듣기 직접 분석, 곡 매칭 문제 없음(느림)
- 캐시(`tracks`) 히트 시 외부 미조회. 미스일 때만 Provider 호출.
- → ReccoBeats가 종료돼도 인터페이스 뒤 구현체만 바꾸면 되고, 이미 캐시된 값은 유지된다.

## 3. 감정 좌표 (valence–arousal)

각 곡과 각 기분을 2차원 좌표로 표현한다. `valence`=정서 긍/부(0 어두움 ~ 1 밝음), `arousal`=각성도(0 차분 ~ 1 격렬, energy로 근사).

### 3.1 기분 → 목표 좌표

| mood | valence | arousal | 후보 장르(Apple) |
|---|---|---|---|
| 기쁨 | 0.90 | 0.75 | K-Pop, Dance, Pop |
| 평온 | 0.70 | 0.25 | 어쿠스틱, Jazz, New Age |
| 보통 | 0.50 | 0.50 | Pop, Indie |
| 모름 | 0.50 | 0.50 | (보정 없이 인기 위주) |
| 답답 | 0.30 | 0.60 | Alternative, Rock |
| 화남 | 0.20 | 0.85 | Rock, Hip-Hop |
| 우울 | 0.20 | 0.30 | 발라드, R&B/Soul |
| 슬픔 | 0.15 | 0.25 | 발라드, 싱어송라이터 |

### 3.2 날씨 보정(Δ) — 좌표를 살짝 이동

| weather | Δvalence | Δarousal | 비고 |
|---|---|---|---|
| 맑음 | +0.10 | +0.05 | 밝게 |
| 바람 | 0.00 | +0.05 | Indie 감성 |
| 흐림 | −0.10 | −0.05 | 차분·저채도 |
| 눈 | −0.05 | −0.10 | 잔잔 |
| 비 | −0.15 | −0.10 | acousticness 가중↑ |

### 3.3 계절 보정(Δ, 일기 월 기준)

봄(3–5) `+0.05 valence` · 여름(6–8) `+0.05 arousal` · 가을(9–11) `−0.05 valence` · 겨울(12–2) `−0.05 arousal`.

> 최종 목표 좌표 = 기분 좌표 + 날씨Δ + 계절Δ, 각 축 `[0,1]`로 클램프.

## 4. 파이프라인 (5단계)

1. **국내/해외 판별** — `seedTrack.artist`에 한글 포함 → `kr` 스토어프론트, 없으면 `us`. seed 없으면 기본 `kr`.
2. **목표 좌표 + 후보 장르 산출** — §3 매핑으로 target(valence, arousal)과 장르 세트 결정.
3. **후보 수집** — 장르별 Apple RSS 차트를 병합(랜덤 페이지 샘플링으로 유명곡 쏠림 완화). seed 있으면 iTunes로 seed 아티스트 곡 + 동일 장르 추가.
4. **감정 거리 랭킹 + 캐스케이드** — 각 후보의 특성(valence, arousal)을 조회, 목표 좌표와의 **가중 거리**로 정렬. 우선순위 캐스케이드(취향 → 기분 → 날씨 → 계절)로 좁히되 후보가 남을 때만 적용. 상위 K개 중 랜덤 1곡(최근 추천 곡 제외).
5. **메타 보강** — 선정곡을 iTunes로 검색해 커버·미리듣기 부착. 매칭 실패 시 최대 5회 재추첨.

### 4.1 거리 스코어(예시)

```
score = wV·(cand.valence − target.valence)²
      + wA·(cand.arousal − target.arousal)²
      + (weather=='비' ? wAc·(1 − cand.acousticness)² : 0)
# 기본 가중치 wV=1.0, wA=1.0, wAc=0.5. score 최소값이 가장 잘 맞는 곡.
```

### 4.2 다양성 확보 (인기곡 쏠림 완화)

차트 상위 몇 곡만 쓰면 "나오던 곡만" 나오므로:
- 차트를 **최대 300곡** 받아 **랜덤 샘플링**
- 한 기분의 **여러 장르 + kr/us** 병합으로 풀 확대
- seed곡 있으면 그 **아티스트·장르 주입**(취향 반영)
- **최근 추천 곡 제외**(예: 14일 윈도우)
- 최근접 1곡이 아니라 **상위 K개 중 랜덤 1곡**
- (장기) 발굴형이 필요하면 차트 밖 롱테일 소량 혼합 — 단 "아는 곡 반가움"을 고려한 블렌드

### 4.3 곡 식별 (cross-service matching)

애플 후보곡을 ReccoBeats 특성에 연결할 때 서비스 간 ID가 달라 매칭이 필요:
- **ISRC 우선**(둘 다 있으면 정확)
- 없으면 **정규화 퍼지 매칭**(소문자화, `feat.`·`(Remaster)`·`(Live)` 제거, 로마자 정규화 후 유사도)
- **신뢰도 낮으면 특성 미부착** — 잘못된 값보다 없는 게 낫다(그 곡은 감정 랭킹 제외/폴백)
- 매칭 결과(ISRC·외부 ID)는 `tracks.isrc`에 캐시 → 재매칭 불필요
- 📌 **Essentia 자체분석은 이 문제를 우회** — 애플이 준 미리듣기를 직접 분석하므로 매칭 자체가 불필요

## 5. 캐싱 / rate limit 대응

- **곡 특성 캐시**: 한번 조회한 valence/energy 등은 `tracks` 테이블에 저장 → 같은 곡 재조회 없음.
- **차트 캐시**: Apple RSS 장르 차트는 **일 단위** 캐싱(차트는 자주 안 바뀜).
- **iTunes 20콜/분**: 위 캐시로 대부분 흡수. 검색은 클라이언트 디바운스. 초과 시 Apple EPF 검토.
- **graceful degradation(실배포 필수)**: ReccoBeats 장애·종료 시 감정 좌표 랭킹을 건너뛰고 **기분→장르→Apple 차트**에서 곡을 반환해 앱이 계속 동작하게 한다. 안정성이 더 필요하면 **Essentia 자체분석**을 폴백/보강으로 사용.
- **pre-warming(선택)**: 매일 밤 오늘 차트(수백 곡)를 배치로 미리 분석·캐시 → 사용자 요청 시 즉시 응답(첫 분석 지연을 사용자 눈에서 숨김).

## 6. LLM 미채택 & 프라이버시 (요약)

- 추천은 **정형 입력(mood·weather·date·seed)**만 사용 → 일기 텍스트가 서버·외부로 나가지 않음.
- LLM으로 일기를 해석하면 품질은 오르나 **사생활·할루시네이션·비용** 리스크. MVP에서는 배제.
- 확장 시: 감정 추출을 **온디바이스**로 수행하고 좌표값(숫자)만 전송. 원문은 기기를 떠나지 않음. (상세 ADR-011)

## 7. 구현 시 확정할 항목

- ReccoBeats 조회 방식 검증(§2 경고). ReccoBeats vs Essentia 비중 결정.
- 곡 식별: ISRC 확보 여부 + 퍼지 매칭 임계값(§4.3).
- 지연 전략: 온디맨드 분석 vs pre-warming 배치(§5).
- 기분→장르 매핑값·좌표값·가중치(wV/wA) 튜닝(실제 청취 테스트).
- "최근 추천 곡 제외" 윈도우 크기(예: 최근 14일).
- **피드백 루프·협업 필터링: MVP 미채택** — 개인별 반응 저장 부담이 크고, 콜드스타트는 콘텐츠 기반으로 해결됨. myTrack 선택이 이미 암묵적 취향 신호. 향후 필요 시 `user_track_feedback` 단일 테이블로 개인용만 추가.
